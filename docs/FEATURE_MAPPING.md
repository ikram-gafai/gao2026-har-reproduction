# Compact-100 feature mapping

**Source:**
- Gao et al. (2026), Supplementary Table S2, kept byte-for-byte at `configs/gao2026_supplementary_table_S2_100_features.csv` (SHA-256 `c84f3d36…a0ff`, CRC-32 `07a9e483`; CC BY 4.0).
- S2 lists 100 feature **names** ranked by global mean |SHAP|. It has **no column indices and no axis field**.

The mapping is generated by `python -m har_repro.cli build-mapping` and committed as `configs/compact100_mapping.json`. `tests/test_mapping_real.py` regenerates it from the official `features.txt` and requires an exact match.

## Result against the official `features.txt`

- `features.txt` has 561 columns, indices 1–561, and 477 unique names.
- 42 names occur exactly three times, and all of them are `bandsEnergy` features. Each signal has three consecutive 14-column blocks.
- Of the S2 names, **91 match exactly one column**. **9 match three columns.** None is missing.

**What the evidence shows:**
- **Block → axis:** the dataset documentation does not state which block is X, Y or Z. On *training rows only*, each block's `1,8` band correlates most strongly with the matching `energy()-X/Y/Z` column for all three signals.
  - Diagonal correlations: fBodyAcc 0.990 / 0.936 / 0.948; fBodyAccJerk 0.898 / 0.818 / 0.733; fBodyGyro 0.981 / 0.851 / 0.956.
  - The weakest margin is fBodyAccJerk block 2: Y 0.818 vs X 0.815.
  - So block 1 = X, block 2 = Y and block 3 = Z (see `results/data_validation/data_validation.json`).
- **Not resolvable:** the paper text, Figure 7 labels, S2 ordering and supplement say nothing about which block the authors used. That cannot be resolved from public information.

**Rule:**
- **Primary (pre-registered):** the first occurrence (X block): 303, 311, 315, 382, 390, 394, 461, 469, 473.
- **Exploratory:** all nine on Y (317, 325, 329, 396, 404, 408, 475, 483, 487), or all nine on Z (331, 339, 343, 410, 418, 422, 489, 497, 501).
- Results from these are reported in full and never used to pick a mapping.

## Identical columns inside the compact set

Five pairs of the 100 columns are **numerically identical** in both partitions. The compact model therefore has 100 named inputs but **95 distinct vectors**. No column is removed, because removing one would change the claimed input configuration and the column sampling.

| Column | Identical to |
|---|---|
| 202 `tBodyAccMag-std()` (S2 rank 97) | 215 `tGravityAccMag-std()` (rank 54) |
| 203 `tBodyAccMag-mad()` (rank 60) | 216 `tGravityAccMag-mad()` (rank 91) |
| 210 `tBodyAccMag-arCoeff()1` (rank 79) | 223 `tGravityAccMag-arCoeff()1` (rank 29) |
| 227 `tBodyAccJerkMag-mean()` (rank 28) | 232 `tBodyAccJerkMag-sma()` (rank 87) |
| 503 `fBodyAccMag-mean()` (rank 66) | 508 `fBodyAccMag-sma()` (rank 20) |

Across all 561 columns there are 19 identical groups (21 redundant columns), so the full set has 540 distinct vectors.

**Consequences:**
- The 82.17% figure counts names. On distinct vectors the reduction is 540 → 95 (82.4%).
- SHAP importance split between identical predictors is not identifiable, so the S2 ranking of these pairs is arbitrary.
- Predictions do not depend on which twin a tree splits on, but column order affects seeded column sampling.
